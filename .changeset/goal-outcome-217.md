One outcome contract for every result (#217). A goal run's `missionOutcome` is now always the canonical verdict (`clean`, `defects-found`, `inconclusive`, `crashed`, `hang`, `intermittent`), folded by the single `GOAL_OUTCOME_FOLD` mapping: `succeeded` → `clean`, `failed`/`exhausted`/`blocked` → `defects-found`. The goal's own ending moves to a new `goalOutcome` field, present on every goal result (additive in result schema version 1; `outcome` still holds the same word). Before, a goal result put `succeeded`/`failed`/`exhausted`/`blocked` in `missionOutcome`, against docs/outcomes.md and `explore --help`. The persisted `<stem>.result.json`, MCP `get_mission_result` (`status` + `goalOutcome`, read from the result), a `check` goal item (`outcome` canonical, `goalOutcome` beside it), a queued mission's record, `report`'s runs table and the human summary (`GOAL <goalOutcome> (stop: …)` under the canonical verdict) all follow it; a result written before this still reads, its goal word folded the same way. A script that compared a goal result's `missionOutcome` with `succeeded`/`failed`/… must read `goalOutcome` instead (or compare `missionOutcome` with `clean`/`defects-found`). A goal whose model kept proposing `done` until code stopped accepting proposals now shows `stop: "done"` (the stop that ended the loop), never `blocked`; its `goalOutcome` stays `failed`. docs/outcomes.md no longer swaps the adversarial `step-budget` (`--max-decisions`) and `action-budget` (`--max-actions`) stops.
