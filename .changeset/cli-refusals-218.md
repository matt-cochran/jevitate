Every command refuses unusable input the same way (#218, the #210 follow-up). **Exit 64, not 2 or 1:** numeric flags are parsed while the command line is parsed (`explore --max-actions abc`, `verify-fix --replays abc|0`, `--stall-timeout`, `--hang-replays`, `--reply-*-ms`, `--hook-timeout-ms`, `load run --concurrency`, `ui --port`, …); `regression run <unknown id>` (`E_REGRESSION_NOT_FOUND`), `regression capture --from <missing file>` (`E_REGRESSION_ARGS`), `ux <missing or invalid recording>` (`E_UX_INPUT`, was `E_UX_RECORDING`), `baseline show <unknown tag>` (`E_BASELINE_NOT_FOUND`) and `invariants validate <unreadable file>` (`E_INVARIANTS_INPUT`, was exit 1). `check` now refuses up front a suite item whose start URL (its own, else the target's) is off the target's allowlist, and a `verifyFix` whose fingerprint is not in its result — they used to fail at runtime as an errored item (exit 2). **Output:** without `--json`, every refusal is `error <CODE>: <message>` on stderr with nothing on stdout — `journey run`, `ux`, `regression run|capture`, `diff`, `baseline`, `report`, `site`, `recording`, `source`, `mission`, `ai`, `mcp` and `invariants validate` used to print the JSON envelope on stdout. With `--json` the envelope is unchanged, and a command line refused while parsing (an unknown flag, a bad number) now also prints one, coded `E_<COMMAND>_ARGS`. A test walks every registered command's refusal paths so a new command cannot regress.
