The pixel mask no longer trusts a page's `requestAnimationFrame` (#547). It uses only the browser's own `requestAnimationFrame`, `MutationObserver`, `getBoundingClientRect` and `Range.getClientRects`, captured before any page script, so a page that replaces them (a polyfill, an animation library, test hooks) cannot make a recorded frame show a secret unmasked. If one was already replaced before the mask loaded, masking fails closed: the whole viewport is painted over, and screenshots and capture sessions are refused with `E_PIXEL_MASK` (reason `untrusted-primitive`).
