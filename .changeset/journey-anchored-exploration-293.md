Journey-anchored exploration (#293). `explore --from-journey <id> --at-step <n|anchor>` (with `--param`, `--env`/`--base-url`, `--journeys-dir`) replays a promoted Journey's first steps in the mission's own browser context — page, form contents and session kept, fail-closed and never self-healed — and starts the goal, coverage, exploratory, adversarial or usability mission on the live page. A prefix that no longer replays ends the run `inconclusive` with `failure.kind: "journey-stale"` (exit 2), never a restart from a URL. Journeys can declare named `metadata.anchors` (`{name, step, description?, probes?}`, validated), listed by `journey anchors <id>`. `campaign run <spec.json>` runs a bounded list of jobs: discovery (each Journey replayed once), then every anchored mission in order with the spec's `--fixtures` restore around each run, and one deduped report (`campaign.json`, `campaign.md`); an invalid spec is refused with every problem listed (exit 64). Results and findings record their branch point (`branch: {journeyId, step, anchor}`, additive, schemaVersion 1); `report` lists each defect's branch points. MCP: `run_exploration` takes `fromJourney`/`atStep`/`params`/`env`/`baseUrl`, plus new `journey_anchors` and `run_campaign` tools; check-suite mission items take `fromJourney`/`atStep`/`params`/`env`/`baseUrl`. `--at-step all|anchors` sweeps every step or anchor (fresh session per stop, fixtures restored, budget split, one deduped report; campaign jobs and suite items too). Resets inside an anchored mission re-replay the prefix (counted against `--max-actions`), and `verify-fix`/`regression capture|run` replay branch-point findings through the prefix (`--param` for secret params; stale → `journey-stale` inconclusive).
