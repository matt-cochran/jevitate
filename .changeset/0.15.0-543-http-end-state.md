`http:` end-state checks prove a write whose effect is off the app's UI (#543), such as a password-reset email in a dev outbox: `--success 'http:GET <url>|jsonPath=$.messages[*].Subject|includes=Reset'` (also `status=`, `equals=`, `exists`, `textIncludes=`, `within=`) on `explore`, `explore-author-journey` and MCP success strings. The check is a polled GET to an origin in the run's allowlist, with no credentials and no redirects followed; the body is capped at 1 MiB and never saved. It satisfies `no-persistence-check`, and `journey run` and `verify --mutate` judge it. A transport error counts as unevaluable, never as mutation proof. New lint rules: `http-check-off-allowlist` (error) and `http-check-without-reset` (warning). A Journey's recorded fixtures may now reach its allowed origins, so they can reset the outbox before every replay.
