UX findings are claims verified by code (#198). `jevitate ux` and `explore --strategy usability` no longer let the rubric report findings on its own. A finding comes from one of three places. A guard probe, which is opt-in (`--probe-guards`, MCP `probeGuards`, suite `probeGuards`). Without it nothing is clicked and guard claims are reported unverifiable. With it, the live run clicks each control the safety policy calls destructive, once per page, on a fresh page. It aborts every non-GET request and every request whose URL, query, RPC name or body names a destructive verb, whatever the method. It refuses a page with an open WebSocket or EventSource or a controlling service worker. It cancels any confirm, never clicks inside a dialog, and closes the page as soon as one appears. It records whether a native confirm, a page dialog or a confirmation page came first and which requests the click attempted; none reach the server. The product facts: `.jevitate/product.json` or `--product <file>` lists plans and prices, trial lengths, key journeys and each page's intended next step; a price or trial on screen that contradicts them is a `fact-conflict`, and a missing or disabled next step is `next-step-unclear`. Observed friction no run signal explains: Jev categorizes it with a claim type from a closed list (or not-a-problem) and a target control from the page's real controls, bounded under the choice cap. Code verifies every claim; one that fails is dropped and counted in `report.claims`. The same claim type on the same page and control merges by code, and Jev's one duplicate choice merges a finding into an earlier one as `contributing`. Two Jev yes/no questions, "do we need this?" and "do we need this to complete and ship this feature?", grade each finding; code maps them to actionable / relevant-minor / generic / wrong with cutoffs from `assets/ux-claims.json` (`finding.grade`). Finding text is built from templates over the verified fields; `--polish` (opt-in) rewrites the recommendation with one generation call. Live findings get a cropped, secret-masked screenshot with the cited control boxed (`finding.screenshot`). The judge stays text-only (the Jev SDK takes no images). The product facts file is validated strictly, and an invalid one is refused with `E_UX_PRODUCT_INPUT` (exit 64) before a browser opens. The guard probes are saved in the evidence sidecar, so offline review verifies the same claims. All output changes are additive (schemaVersion 1); see docs/ux-findings.md and the upgrade notes.
