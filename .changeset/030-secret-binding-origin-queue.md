Over MCP, `verify_journey`, `journey_readiness`, `chain_journeys`, `demo_journey`, `run_load_test`, `run_exploration --fromJourney` and shorten now give a Journey the operator's `targets.json` `secretFields` only under the run-mode rule `run_journey` already follows: a promoted Journey, with an approval a person made on an automation-mode target. A draft never gets them. A `--secret-field` binding now goes only to origins a person or operator named (the run's origin, the environment's, `--allow`), never to an origin only the Journey's `allowedOrigins` lists. A navigate URL that would carry the secret anywhere else is refused `E_SECRET_ORIGIN_REFUSED` before any browser opens, and so is a field on such a page. The queue drain refuses a hand-edited queued call that carries a value for a declared-secret parameter (`E_SECRET_PARAM_IN_QUEUE`). It masks a failed call's error before storing it, and `get_mission_result` masks it again when it returns it. An upload refusal names a secret path by its `${name}` reference, not its value. An extracted value whose name holds a credential term and ends in a describing word (`apiKey_name`) is masked if it is credential-length. `verify-fix` masks `--param` values from 3 characters, and credential-named ones at any length. A declared 3–5 digit secret is masked even inside a longer number.
