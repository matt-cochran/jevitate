**Behaviour change over MCP.** A Journey that needs a secret parameter (declared `secret: true`, or named like a credential) no longer runs over MCP: `E_SECRET_PARAM_OVER_MCP`, before anything runs, on `run_journey` with or without a value, and for a value on `verify_journey`, `journey_readiness`, `chain_journeys`, `demo_journey`, `annotate_journey`, `run_load_test`, `run_exploration` and `sources`. These calls used to run with the value, which meant it had passed through the model. A person runs such a Journey on the CLI, or it uses a stored session. `${setup.x}` references are unchanged, and so are params that are not secret, with one exception: a name that reads as a credential, described below. A secret in a `navigate` URL now runs on the CLI only.

`journey run` takes `--secret-field '<label|testId|id|name>=<value>=env:<VAR>'`, the binding a Journey is authored with, and on the CLI `targets.json` `secretFields` apply to it with `--env` or `--base-url`, so a secret parameter stays off the command line. `--param` with a secret parameter keeps working on the CLI and now warns on stderr. See `docs/journeys.md`.

Which names count as credentials changed, everywhere that name check is used. It is now deliberately broad, and adds `pwd`, `authorization`, `auth`, `bearer`, `jwt`, `pin_code`, `privateKey`, `accessKey`, `key`, `mfa`, `ssn`, `cvv`, `csrf`, `signature`, `nonce`, `card_number`, `webhook_url` and foreign words for password, so these are redacted and refused over MCP. A stored Journey under such a name still loads: assertion references and request-body shapes keep their older, narrower rule. `passengers`, `token_count` and other ordinary names that match stay refused over MCP until the parameter declares `"secret": false` and a person approves that Journey (a typed `journey promote` or a verified PR review). An approval over MCP, a scripted or unrecorded one, or a stale one lifts nothing, and a source's Journey can't lift it.

A value `--secret-field` or `targets.json` supplies goes in only at a field on its own origin (the entry's, or for the flag the run's allowlist), checked on `fill`, `select` and `editText` with the field in hand: anywhere else, as after a redirect, the step fails with `E_SECRET_ORIGIN_REFUSED`, and a `navigate` URL or `http` check holding one refuses before anything runs. Two secret parameters on one binding, or two bindings on one parameter, now refuse instead of typing a guessed value. A fixture output named like a credential is redacted and left out of `fixtures.outputs`, in `secretOutputs` or not.

**Capability cost: a secret-bound Journey can't self-heal or be annotated in 0.29.0.** Nothing secret-bound goes to a model. A Journey with a secret parameter, a fixture secret or credential-named output, or a step that can extract a credential skips self-heal from step 1, and the step fails saying why. `journey annotate`, `annotate_journey` and `create_demo` refuse such a Journey with `E_MODEL_REFUSED_SECRET`. This reaches working Journeys whose only secret is a broad name: `passengers=2` or `extract as: "token_count"` loses self-heal and annotate until a parameter of that name declares `"secret": false` and a person approves the Journey, which both refusals now say. `explore --strategy coverage|exploratory` refuse `--secret` with `E_EXPLORE_SECRET_UNSUPPORTED`; `--feature` now masks it in its transcript, Recordings and result, and on the model paths masking now comes before every cut, busy indicators and hang replays included.

A run that would type or navigate with masked text fails (`E_REDACTED_VALUE`) instead of reporting `ok`, and `journey chain` hands a consumer the value as extracted, except under a name like `apiKey`. A stale `secret: false` lifts nothing on the CLI either. `verify-fix` and `regression` `--param` warn for a secret parameter.

With `HOME` overridden and the working directory below the account's real home, the real `~/.jevitate` no longer reads as a project, so logs stay under `HOME`. It still counts when it holds an `environments.json`, when the home is the working directory's git root, or, outside any repo, when it holds no per-user files. The review sheet warns about `secret: false` on a credential-like name.
