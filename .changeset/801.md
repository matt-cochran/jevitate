`jevitate journey shorten <id> --job <jobId> [--budget n] [--out-id <id>]` (#801): an authoring-time search for a shorter path to the same job, with no model. It removes steps (delta debugging), replays every candidate in full with the Journey's fixtures (or `--fixtures`) set up before and restored after it, and decides each one only by the job's done check, read in a fresh browser context. It never drops a click on a confirm, agree or accept control, and never keeps a navigate past one it dropped; those candidates cost no replay. The budget (default 30 replays) includes the recorded path's own replay. The output is a new, unpromoted draft Journey (`<id>-shortest`) and a report of the original steps, the shortest found and the replays used; the source Journey is not changed, and a person reviews and promotes the draft. The result is the shortest path found within the budget, not a proven optimum, and it is only as honest as the done check: a weak check lets a path that skips real work through. Over MCP it is the new `shorten_journey` tool (the same report): draft Journeys only (a promoted one is refused `E_JOURNEY_SHORTEN_PROMOTED`), under `run_journey`'s run-mode gate and run guard (an unapproved draft runs on a test-mode target only), and a secret parameter is refused by name (`E_SECRET_PARAM_OVER_MCP`).
