A secret in a `navigate` URL, such as an invite token, now has a route off the command line (#819). `--secret-field 'param=<name>=env:<VAR>'` binds a secret parameter by its name, wherever the Journey uses it, and the same spec works in `~/.jevitate/targets.json` `secretFields`. A bound value goes only to its binding's origin: the replay checks the URL as resolved before it navigates, and a URL whose literal origin is another one is refused with `E_SECRET_ORIGIN_REFUSED` before anything runs. Over MCP, on an automation-mode target, `run_journey` sends it from the operator's `targets.json` binding for that origin. With no binding, the run is refused with `E_SECRET_MODE_UNAVAILABLE` before any browser opens, and the message names the binding, because a person can't type a URL at a hold. The `--param` warning now names the `param=<name>` binding, which works for a URL secret. A goal run never matches a `param=` binding to a field.
