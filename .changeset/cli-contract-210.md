One CLI contract for every command (#210). **Exit codes:** `0` ok · `1` defects (defects found, a gating finding, still reproduces) · `2` inconclusive (the run or command could not finish: inconclusive/crashed, an errored `check` item, a queued mission that could not run, an unexpected error) · `3` hang · `4` intermittent · `64` usage/input error, where nothing ran · `130`/`143` killed. Usage errors used to exit `1` on `explore` (the same as defects found, e.g. `E_EXPLORE_ARGS`, `E_EXPLORE_ASSERTION`) and `2` on `check`/`ledger`/`verify-fix`; they now exit `64` everywhere, and so do commander parse errors (an unknown option or a missing argument). Other refusals that used to exit `1` now exit `2`. The table is documented once, in docs/outcomes.md "Exit codes". **Output:** with `--json`, every command prints exactly the `{v, ok, data | error}` envelope, unchanged. Without `--json`, `explore` prints a human summary for every strategy: the verdict, counts, each defect and hang with its fingerprint, the result file and a `next:` step. Before, a goal or coverage run printed the bare result JSON and an adversarial, feature or usability run printed the envelope. `ledger list|add|verify`, `verify-fix` and `check` refusals print human text too (a refusal is `error <CODE>: <message>` on stderr), and `init` reports each feature's keys as `ready — n/n configured` instead of `keys: {json}` with `collected: []`. A script that parsed `explore`, `ledger` or `verify-fix` output without `--json` must now pass `--json`.
