# @jevitate/cli

## 0.2.0

### Minor Changes

- f75b99c: One CLI contract for every command (#210). **Exit codes:** `0` ok · `1` defects (defects found, a gating finding, still reproduces) · `2` inconclusive (the run or command could not finish: inconclusive/crashed, an errored `check` item, a queued mission that could not run, an unexpected error) · `3` hang · `4` intermittent · `64` usage/input error, where nothing ran · `130`/`143` killed. Usage errors used to exit `1` on `explore` (the same as defects found, e.g. `E_EXPLORE_ARGS`, `E_EXPLORE_ASSERTION`) and `2` on `check`/`ledger`/`verify-fix`; they now exit `64` everywhere, and so do commander parse errors (an unknown option or a missing argument). Other refusals that used to exit `1` now exit `2`. The table is documented once, in docs/outcomes.md "Exit codes". **Output:** with `--json`, every command prints exactly the `{v, ok, data | error}` envelope, unchanged. Without `--json`, `explore` prints a human summary for every strategy: the verdict, counts, each defect and hang with its fingerprint, the result file and a `next:` step. Before, a goal or coverage run printed the bare result JSON and an adversarial, feature or usability run printed the envelope. `ledger list|add|verify`, `verify-fix` and `check` refusals print human text too (a refusal is `error <CODE>: <message>` on stderr), and `init` reports each feature's keys as `ready — n/n configured` instead of `keys: {json}` with `collected: []`. A script that parsed `explore`, `ledger` or `verify-fix` output without `--json` must now pass `--json`.
- f75b99c: Demo mode: watch a run (#245). Headless stays the default everywhere, `check`/CI included. `--headed` (or `JEVITATE_HEADED=1`) opens a visible Chromium for every `explore` strategy, `journey run`, `verify-fix` and `regression capture|run` — including hang-replay, observer and verify-fix replay sessions. `--slow-mo <ms>` sets Playwright's `slowMo` (a non-negative integer, else exit 64; 250 by default with `--headed`). `--record-video [dir]` (`explore`, `journey run`, `verify-fix`) records each browser context, headless too, into a per-run `<run>.videos/` folder next to the result; the contexts are closed before the result is written, and the files are listed as `videoPaths` (an additive field of the unified result schema, `schemaVersion` 1) and as `VIDEO` lines in the human summary. `--no-overlay` hides the on-page overlay of a headed explore run. `--headed` without a display (no `DISPLAY`/`WAYLAND_DISPLAY` on Linux) is refused before any browser launches (exit 64, suggesting `--record-video`); a headed `--repeat`/`--persona`/`--actor` run prints a one-line warning and shows every window. A `check` suite item takes `headed`, `slowMo`, `recordVideo` and `overlay`. Queued (`mission run`/MCP) missions stay headless. The adversarial and feature runners' unused `headless` option is gone: headedness comes from the `browser` option like every other runner's.
- f75b99c: Finding ledger (#195): `jevitate ledger add <result> <fp> [--ticket X]` stores what `verify-fix` needs to re-check a finding in the committed regressions store (`.jevitate/regressions/ledger/<fp>.json`). `jevitate ledger verify [fp...]` re-checks every entry, or the named ones, and `jevitate ledger list` shows them. `verify-fix` now works from a fingerprint alone: `jevitate verify-fix <fp>` replays the ledger entry when no `--result` is given. Entries hold only the redacted repro material: the finding and its Recording, the scope, the invariant and fixture specs, and the names of controls that sent writes. They never hold a storage state or its path. `--secret` refuses an entry that would contain a named value.
- f75b99c: One outcome contract for every result (#217). A goal run's `missionOutcome` is now always the canonical verdict (`clean`, `defects-found`, `inconclusive`, `crashed`, `hang`, `intermittent`), folded by the single `GOAL_OUTCOME_FOLD` mapping: `succeeded` → `clean`, `failed`/`exhausted`/`blocked` → `defects-found`. The goal's own ending moves to a new `goalOutcome` field, present on every goal result (additive in result schema version 1; `outcome` still holds the same word). Before, a goal result put `succeeded`/`failed`/`exhausted`/`blocked` in `missionOutcome`, against docs/outcomes.md and `explore --help`. The persisted `<stem>.result.json`, MCP `get_mission_result` (`status` + `goalOutcome`, read from the result), a `check` goal item (`outcome` canonical, `goalOutcome` beside it), a queued mission's record, `report`'s runs table and the human summary (`GOAL <goalOutcome> (stop: …)` under the canonical verdict) all follow it; a result written before this still reads, its goal word folded the same way. A script that compared a goal result's `missionOutcome` with `succeeded`/`failed`/… must read `goalOutcome` instead (or compare `missionOutcome` with `clean`/`defects-found`). A goal whose model kept proposing `done` until code stopped accepting proposals now shows `stop: "done"` (the stop that ended the loop), never `blocked`; its `goalOutcome` stays `failed`. docs/outcomes.md no longer swaps the adversarial `step-budget` (`--max-decisions`) and `action-budget` (`--max-actions`) stops.
- f75b99c: Tell a starved host apart from app findings (#203). Every run samples the host's health (the browser pool's admission thresholds, load average per core, the driver's event-loop lag, and the render trend against the run's own baseline), and every result now carries `hostHealth` (peak load per core, minimum free memory, peak event-loop lag, slowest render, starved steps) and `environmentDegraded`. A hang, click timeout or no-progress stop met while the host was starved is listed there as advisory, never as a defect or hang finding. A run most of whose steps ran starved is `inconclusive` with `failure.kind: "degraded-environment"`, never `clean`. A coverage or exploratory frontier that emptied because its actions timed out now ends `insufficient-exploration` (inconclusive), not `exhausted`. Both fields are additive to result schemaVersion 1. `JEVITATE_HOST_STARVATION=off` keeps the sampling but disables the attribution.
- f75b99c: HTTP 5xx is a hard-signal defect in every strategy (#208). Goal, feature, coverage/exploratory and usability runs now record a 5xx from the app's own origins as an `http-5xx` defect in `defects`, with the same fingerprint the adversarial strategy gives it (endpoint pattern + status), so `verify-fix` replays it the same way. A goal run whose success checks held but whose run hit a 5xx ends `defects-found` (exit 1), never `succeeded`: `assertionPassed`/`checks` keep the checks' verdict and `reason` names the failing request (`PUT /demo/api/profile → 500`). An adversarial run whose start page itself answers 5xx reports that as an `http-5xx` defect (`defects-found`, `stop: "not-rendered"`) instead of an inconclusive "not rendered". A 5xx from a third-party origin (#194) is not the app's defect, in every strategy. In a usability run the defect is listed with `advisory: true`, like its `server-log` defects.
- f75b99c: Journeys are environment-free (#247). Name the places your app runs in a committed `.jevitate/environments.json` (`{ "<name>": { "baseUrl", "allow"?, "fixtures"?, "hooks"? } }`; `jevitate init` writes an example once and never overwrites it) and choose one at run time with `--env <name>` or `--base-url <origin>` on `journey run`, `regression run` and `load run`, or with `env`/`baseUrl` on a check-suite Journey item. The Journey's recorded same-origin URLs move onto the environment's `baseUrl`, and the run's allowlist is the environment (`baseUrl` + `allow`): a step on any other origin is refused with exit 64 before any browser opens, and so is an unknown `--env` (the message lists the known ones). The file never holds secrets or sessions: a `storageState`/`secret`/`password`/`token`/`cookie`/`credential` key is refused. Per-environment sessions and secret fields stay in `~/.jevitate/targets.json`, keyed by the environment's origin (`storageState`, `secretFields`, and new `personas: { "<name>": { storageState?, secretFields? } }`). Without `--env`/`--base-url` a Journey runs on its recorded site exactly as before.
- f75b99c: Journeys can now say why, not only what (#246). Every new field is optional and additive, so an existing Journey validates and runs unchanged. At the Journey level they are `metadata.goal`, `persona`, `role`, `preconditions` (linked to fixtures and hooks), `successCriteria` (each with an optional code `check`) and `parameters` (`secret: true` marks a value for redaction). Each step gets `objective` and `expectedResult`. A new command, `jevitate journey annotate <id> --real|--fake-ai`, replays the Journey, reads the redacted page before and after each step, and drafts the missing objectives and expected results, plus the goal and success criteria, into `.jevitate/journeys/.drafts/<id>.annotations.json`. It never writes the Journey. `journey annotate <id> --approve` is the human gate: it shows the diff, then writes the reviewed draft. It refuses a draft made against a Journey that has changed since (`E_JOURNEY_ANNOTATIONS_STALE`, exit 64). A secret parameter's value is redacted in the `journey run` output, in annotate's evidence, drafts and output, and in anything sent to a model. `journey run` also reports how many steps lack an objective; this is informational and never fails. See docs/journeys.md, "Journey format reference" and "Annotate a Journey".
- f75b99c: Truthful outcomes (#209) — a published contract change. A run that proved nothing is never `clean`, its reason is named, and every defect is in `defects`:
  
  - **Goal:** a new `failed` outcome (exit 1, folds onto `defects-found`) for a run whose model said `done` but whose independent success check then failed, with `failure.kind: "success-check-failed"` naming the check. It was `blocked`, which now only means the loop gave up. A run whose only failing checks are vacuous (#202) is now `inconclusive` (exit 2), with `failure.kind: "vacuous-check"` instead of `blocked`. Its check detail no longer ends with "held on the final page". While a check is still pending (a `reloadThen`, or a check that has held since before any action), the transcript records the model's `done` as "accepted provisionally" instead of "goal verified by success-condition".
  - **Usability:** a review whose job was never completed is `inconclusive` with `failure.kind: "job-incomplete"`. It used to be `clean`.
  - **Feature:** a run whose every exercised control was unrelated to the feature (all `relevance=0`) is `inconclusive`, the same as the chrome-only case. Both the frontier `outcome` and `failure.kind` are `insufficient-coverage`. It adds `coverage.relevantActionsExercised` and `coverage.featureWords`.
  - **Adversarial:** when every target control is refused by the safety policy, the run stops early with the new stop reason `targets-refused` and reports `coverage.controls.refused`. The failure names the refused controls and the flags that permit them (`--allow-destructive`, removing a `--deny`, or `--paid`/`--deny` to reclassify a control).
  - **Coverage / exploratory:** each ending now has one name. The frontier outcome and the failure kind are both `insufficient-coverage` (#203's `insufficient-exploration` is renamed), and `exhausted` now means the frontier was fully covered. Links in the page body count as coverage, while only chrome links (`<nav>`/`<header>`/`<footer>`, or links repeated across pages) count as global navigation. The shortfall now says how to reach `clean`.
  - **Defects:** a coverage run's frontier defects (`horizontal-overflow`, `judgment-flagged-state`) are now also in top-level `defects`, each with a `fingerprint` and `kind`.
  - Goal outcomes map to exit codes in one place: `GOAL_OUTCOME_FOLD` / `outcomeExitCode()` in `@jevitate/domain`.
- f75b99c: One versioned result schema across explore strategies (#195). Every goal, coverage, exploratory, adversarial, feature and usability result now carries `schemaVersion: 1`, `strategy`, `missionOutcome`, `exitCode`, `defects`, `hangs`, `recordingPaths`, `transcriptPath`, `resultPath`, `target` and `engine`, filled the same way by every strategy. `defects` now holds every defect, `server-log` ones included; a usability run's server-log defects are marked `advisory: true` and still never gate its outcome. `recordingPaths` is always an array. Persisted results now always include `resultPath`. The schema is exported as `MissionResultSchema`, `PersistedMissionResultSchema` and `MissionResultCore` (see docs/results.md). Deprecated for 0.2.0 only and removed in the next minor: `serverLogDefects` (use the `server-log` entries in `defects`) and `recordingPath` (use `recordingPaths[0]`).
- f75b99c: Jevitate v0.2.0: autonomous browser testing that turns discovered bugs into deterministic regression tests.
  
  - **Reproduce, verify, lock in.** `verify-fix` replays a finding 3 times in fresh browser contexts and reports `intermittent` (exit 4) instead of a lucky `fixed`. A new finding ledger (`jevitate ledger add|list|verify`) keeps the repro material in the repo, so `jevitate verify-fix <fp>` works from a fingerprint alone. `regression capture` accepts failed success checks, network checks and declared-invariant violations as its oracle, never the engine's own refusals, and `regression run <id>` replays a committed regression.
  - **One result contract.** Every strategy writes the same versioned result (`schemaVersion: 1`): `missionOutcome` is always the canonical verdict (a goal's own `succeeded`/`failed`/`exhausted`/`blocked` is in `goalOutcome`), `defects` holds every defect, and `hostHealth`/`environmentDegraded` tell a starved host apart from app findings. Code decides defects: an HTTP 5xx is a defect in every strategy, while a state flagged only by Jev's judgment is advisory. A run that proved nothing (too little coverage, a vacuous check, a starved host, an app that stopped answering, a usability job never completed) is `inconclusive`, never `clean`; an unreachable target fails in seconds.
  - **One CLI contract.** One exit-code table for every command (`0` ok · `1` defects · `2` inconclusive · `3` hang · `4` intermittent · `64` usage/input error · `130`/`143` killed), a human summary by default and the unchanged `{v, ok, data | error}` envelope with `--json`, and every refusal as `error <CODE>: <message>` on stderr.
  - **App-declared invariants.** `--invariants` checks your own rules (DOM, network, `never.response` and read-only probes, including authenticated probes and cross-actor isolation checks) around every action; `jevitate invariants validate` checks the file without a browser.
  - **CI gate and reporting.** `jevitate check --suite` runs Journeys, goals, missions (whose items take every `explore` option), invariant sweeps and re-checks within a budget, writing JUnit and SARIF. `jevitate report`, `diff` and `baseline` give one deduped defect list and new / resolved / flaky classification.
  - **Real apps.** Bound secrets typed by code, `--secret env:VAR`, TOTP, `--save-storage-state`, mission fixtures around every run and replay, authenticated queued missions via `targets.json`, backend log correlation, `--repeat`/`--min-agreement` voting, persona matrices, multi-actor missions, site policies for Journey runs, and a repo-local `.jevitate/` with shared Journeys.
  - **Safer by default.** Session-ending, destructive and paid controls are refused unless you pass `--allow-destructive`; find-out goals are read-only unless you pass `--allow-writes`, and an off-site write passes only when it carries no credentials to an origin the app authenticates with; hang replays never re-send a paid write; secrets shown on the page are redacted; profile names and regression ids cannot escape their directories; runs are bounded by a page watchdog, and killed runs still write a result.
  - **Better goal runs.** Network, persistence and visual-state checks with a vacuous-check rule, rich-text edits in `contenteditable`, find-out answers grounded in page text and form values that must actually answer the question, conversational-page handling, and usage with the full run cost (Jev priced by default).
  
  - **Demo mode and evidence.** `--headed`, `--slow-mo <ms>` and `--record-video` let you watch or record any run (headless stays the default, CI included), with an on-page overlay jevitate itself cannot see. Journeys carry intent (goal, success criteria, per-step objective and expected result): `journey annotate` drafts it on playback and you approve it, and `--env <name>` runs a Journey on a named environment from `.jevitate/environments.json`. `journey demo` renders a Journey as a narrated video with `.vtt` subtitles and a Markdown guide, and `demo "<aspect>"` explores, minimizes, annotates and drafts one from a one-line request that `demo approve` promotes. `--evidence-video` attaches a captioned clip and before/at screenshots to each defect (`defects[].evidence`, also in drafts, `report`, JUnit and SARIF), `verify-fix --record-video` records a before/after pair, `--screenshots [screens|steps]` writes an indexed screenshot set, and registered secrets are masked in the pixels of all of it.
  - **CLI and MCP parity.** `inbox list|show|command|queue-retrieval|queue-action|health`, `mission queue` and `mission result` join the CLI (`inbox command` needs `--reveal` to consume unread human input); every CLI command is reachable over MCP, with new tools (`annotate_journey`, `demo_journey`, `create_demo`, `approve_demo`, …) and richer `run_journey`, `verify_fix` and `queue_exploration` options, and every MCP tool is reachable from the CLI, guarded by a test both ways. The tool allowlist boundary is unchanged.
  
  Upgrading from 0.1.0: parse `--json` (human output is now the default); usage errors exit `64`; compare a goal's `missionOutcome` with `clean`/`defects-found` or read `goalOutcome`; `insufficient-exploration` is now `insufficient-coverage`; `--success` is refused on coverage/exploratory/adversarial/feature runs and enforced on usability; coverage, exploratory and `--feature` runs are scoped to the start route by default (`--scope app`/`--route` to widen); the default safety policy refuses destructive and paid clicks; `textIncludes` is case-insensitive; `verify-fix` exits 4 for intermittent findings; `ledger verify` with no entries exits 2; exploratory results are named `exploratory-*`; a bare `report`/`diff` reads only the current project's runs; `--real --fake-ai`, an unknown `--strategy` and re-capturing an existing regression id without `--force` exit 64; and `serverLogDefects`, `recordingPath`, `usage.usd` and `usage.jevPriceSource` are deprecated aliases. See CHANGELOG.md for the full list.
- f75b99c: A goal's success check that was already satisfied before the run's first action now fails as vacuous (#202): a page or `reloadThen` check that held on the seed page and never stopped holding (an empty result container rendered at once), or a `requestMade`/`responseStatus` matched only by a page-load or polling request. The result names it in `checkWarnings` (`check '<spec>' held at step 0, before any action — it cannot verify the goal`). Network checks now count only requests sent after the run's first action. `--allow-vacuous-checks` (suite: `allowVacuousChecks` on a goal item or target) downgrades a vacuous check to a warning.

### Patch Changes

- f75b99c: Every command refuses unusable input the same way (#218, the #210 follow-up). **Exit 64, not 2 or 1:** numeric flags are parsed while the command line is parsed (`explore --max-actions abc`, `verify-fix --replays abc|0`, `--stall-timeout`, `--hang-replays`, `--reply-*-ms`, `--hook-timeout-ms`, `load run --concurrency`, `ui --port`, …); `regression run <unknown id>` (`E_REGRESSION_NOT_FOUND`), `regression capture --from <missing file>` (`E_REGRESSION_ARGS`), `ux <missing or invalid recording>` (`E_UX_INPUT`, was `E_UX_RECORDING`), `baseline show <unknown tag>` (`E_BASELINE_NOT_FOUND`) and `invariants validate <unreadable file>` (`E_INVARIANTS_INPUT`, was exit 1). `check` now refuses up front a suite item whose start URL (its own, else the target's) is off the target's allowlist, and a `verifyFix` whose fingerprint is not in its result — they used to fail at runtime as an errored item (exit 2). **Output:** without `--json`, every refusal is `error <CODE>: <message>` on stderr with nothing on stdout — `journey run`, `ux`, `regression run|capture`, `diff`, `baseline`, `report`, `site`, `recording`, `source`, `mission`, `ai`, `mcp` and `invariants validate` used to print the JSON envelope on stdout. With `--json` the envelope is unchanged, and a command line refused while parsing (an unknown flag, a bad number) now also prints one, coded `E_<COMMAND>_ARGS`. A test walks every registered command's refusal paths so a new command cannot regress.
- f75b99c: Find-out answers must answer the question (#223). An answer is now rejected when its quote is only an action or label name (a button, a form field's label, or a navigation/header/footer or repeated link; a link in the page's content, such as an item title in a list, still counts as content), or when it sits on an error page (the document answered HTTP 4xx/5xx, or its heading or title says not found / 404 / error). Such a run ends "answer not found". An independent Jev check, "does this quote answer the goal's question?", can veto an answer that code grounded, but it can never approve one on its own. A `<textarea>` value, or the text of a contenteditable field, now grounds an answer as a form field value, the same way an input's value does.
- f75b99c: Find-out goals answer from ordinary page text and form values (#207). A read-only find-out goal's decisions now carry the page's visible text (redacted, bounded), so an answer in a table cell or heading is seen and reported; a model `blocked` on such a goal first becomes one grounded report attempt on that page state (never an answerless "goal already met"). A form control's current value (never a password / one-time-code / bound secret field) is a grounding source: evidence records `source: "control-value"` and the control, while page-text quotes record `source: "page-text"`. A run whose report found no answer ends "answer not found (pages seen: …)" instead of a generic no-progress / blocked reason, and a literal "null" answer counts as no answer.
- f75b99c: A state flagged only by Jev's judgment is advisory (#214). In coverage and exploratory runs, a `judgment-flagged-state` defect now carries `advisory: true` in `defects` and `coverage.defects`. It keeps its repro Recording, so `verify-fix` can still replay it, but it never sets `missionOutcome` or the exit code on its own. A run whose only finding is a flagged state now ends `clean`, or `inconclusive` when it exercised too little; before, it ended `defects-found` with exit 1. The run is `defects-found` only when an independent code oracle confirms a defect: an HTTP 5xx, a horizontal overflow, a declared invariant or a server-log defect. `check` and `report` read a flagged state as an advisory finding, the same as before, and the human summary counts it as advisory.
- f75b99c: Security: a profile name or regression id can no longer escape its directory (#221). `profile create ../x` used to create a directory outside the profiles folder (profiles hold browser sessions). Profile names (`profile create|status`) and regression ids (`regression capture --id`, `regression run <id>`) must now be one safe path segment — 1–128 letters, digits, `.`, `_` or `-`, starting with a letter or digit, no `..`, `/`, `\`, NUL or absolute path — checked by one shared helper that also verifies the resolved path stays inside its root. A refusal is `E_INVALID_NAME`, exit 64.
- f75b99c: Usability runs recognise a completed save, and honour `--success` (#225). **Done-recognition:** the goal judgment now sees the page's form fields and their current values (a field's value is never in the page text, yet it is where a form shows what was saved — non-secret values only, never a bound secret or a message composer). Code evidence is preferred over the judgment's probability: when the run submitted its typed values, every write the submit fired finished 2xx, a success notice ("Saved") and no failure shows, and the page still displays each saved value, `done` is accepted as `verifiedBy: "save-signals"` — if the advisory scope head says the whole goal is that save (the #188 sign-in pattern). A save answered by a 4xx/5xx is never such evidence, even when the page says "Saved". **`--success` for `--strategy usability`** (and a usability suite mission's `success`/`successWhen`, `allowVacuousChecks`): an independent completion check with a goal run's semantics — it grounds `done`, the #202 vacuous rules apply, and the verdict folds like a goal run's (`goalOutcome`, `checks`, `checkWarnings` in the result; a failed check is `defects-found`, exit 1). It used to be silently ignored; an unparseable one, or `--success-when`/`--allow-vacuous-checks` without one, is now refused (64). A usability run whose check fails reports `failure.kind: "success-check-failed"` naming the check, and stops as soon as the job is judged done on the page but the check failed, instead of spending the whole action budget. `--strategy coverage|exploratory|adversarial` and `--feature` now refuse `--success`, `--success-when` and `--allow-vacuous-checks` (64, `E_EXPLORE_ARGS`) instead of silently ignoring them; suite items of those strategies already refuse them.
